# 歷史主題資料集：預留介面

狀態：已提供通用資料集開關與排序，現有來源為私人、台灣、國際。未來主題內容、主題匯入及下載尚未實作。

## 資料介面

`src/calendar/history.ts` 提供：

- `HistoryEntry`：沿用日期、年份、標題、摘要、地區及選填來源欄位，新增選填 `tags` 字串陣列。
- `HistoryDataset`：`id`（穩定識別碼）、`label`（顯示名稱）、`kind`（personal／regional／topic）、`entries`（紀事陣列）、選填 `defaultEnabled`（預設啟用狀態）。
- `historyDatasets`：目前只登錄個人、台灣、國際三份本機 JSON，預設順序為私人 → 台灣 → 國際。
- `composeHistory(datasets)`：合併已提供的資料集，保留資料集與紀事順序；不負責下載、儲存或切換設定。

既有 JSON 維持陣列格式，不需加上資料集外層，也不用補 `tags`。資料集名稱與事件地區分開：例如科技主題中的台灣事件仍填 `region: "台灣"`，不將地區改成「科技」。

## 未來實作接點

1. 各主題新增獨立 JSON 紀事陣列，透過 `HistoryDataset` 登錄，避免修改台灣／國際／個人資料。
2. 現有「紀事來源與順序」由登錄資料集自動產生，支援多選與上下排序。設定保存於 `preferences.historySources`，以穩定 `id` 與 `enabled` 記錄；新主題追加至清單末端，預設關閉，可由 `defaultEnabled` 覆寫。
3. `setHistorySources` 已依來源順序及啟用狀態重建日期索引，並刷新畫面；個人匯入同樣沿用來源設定。資料集內維持 JSON 順序，不以事件的 `region` 判定來源。`normalizeHistorySources` 會去除重複及未知識別碼，補入新登錄來源。
4. 主題可能和地域資料重疊，正式實作時須決定穩定事件 ID、跨資料集去重及每日顯示筆數；目前預設顯示三則，可按「顯示更多」展開當天全部紀事。
5. 補上主題資料驗證規則。現有 `data:check-history` 的 9～12 月覆盖與台灣占比統計只針對公開地域資料，不應直接套用到各主題。
6. 日期須區分發表、上市、首播、首映與地區版本，引用可查證來源；目前不新增未查核事件。

目前沒有主題 JSON 空檔、網路載入、額外權限；目前只有既有資料集的設定選項。CSV／XLSX 工具維持現有私人紀事轉換功能，尚不提供主題分類與 tags 編輯。
